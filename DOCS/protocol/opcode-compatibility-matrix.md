## How to regenerate

```powershell
python .agents/research/opcode-matrix.py matrix --tsv .agents/research/client748/inventory/opcode-matrix.tsv --markdown DOCS/protocol/opcode-compatibility-matrix.md --native-export .agents/research/client748/exports/opcode-census-native.tsv
```

The native side needs the decompiled corpus in
`tmproject/build/native-research/decompiled/` (ignored). It is produced from the
Ghidra project `tmproject/build/native-research/WYD748.gpr` by
`ExportWydOpcodeSites.java` (headless, `-readOnly -noanalysis`); see
`.agents/skills/wyd-client748-research/scripts/`. Client sizes are asked from
the compiler with the recorded Debug|Win32 options.

Limits of the extractors: a row is a lead, not a contract. Native receive is
found from comparisons and `switch` labels on the packet `Type` field; native
send from a header built in consecutive locals and passed to a call, sized by
that call or by the `memset` that clears it, or from an opcode stored into an
object field (prebuilt packets). A field that receives several values in one
function counts only when every value is a known opcode; otherwise it is a
selector (for example `FUN_0053aaed`, an index table, not a packet). A field
whose buffer is cleared by a `memset` starting four bytes before it is a packet
header (Size at +0, Type at +4); its opcode counts even when no source knows it.

Completeness: 193 rows are native. The size gate lists 133 opcodes and the
other 60 come from native code. Static analysis cannot prove that no other
native opcode exists: an opcode computed at runtime, passed through a register
or built in a heap buffer by another pattern is not seen. Two independent
checks were run on 2026-10-03:

- An instruction-level scan of all 430,127 instructions in 4,146 functions
  (`ExportWydTypeFieldScan.java`; filtered result in
  `.agents/research/client748/exports/opcode-scan-type-field.tsv`) found no
  receive opcode outside the matrix: every comparison of the `Type` field and
  every switch case label is already listed. It also exposed three gate
  opcodes the decompiler printed in decimal (0x2BC, 0x383, 0x384), now parsed.
- Every word written into an object field was reviewed. One was a real packet
  unknown to the three sources: 0x3B8 (below). The rest are selector fields,
  sentinels (0xFFFF, 0xFFFE, 0x8000), the bitmap signature 0x4D42, or timers.

A handler that only consumes a packet with a
stub (for example the `0x7BE/0xFBC/0x13BD` "need to decompile" branches in
`TMScene`) counts as received here; such stubs are listed below.
