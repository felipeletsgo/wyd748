# TMProject dead-code map

Final audit of the client (`tmproject/TMProject748`) for code that is dead,
has no function, or serves no 7.48 contract. Generated by
`.agents/research/dead-code-map.py`; the sections from "Summary" on are
rewritten by the tool, this introduction is kept.

## Method

1. **Linker reachability (authoritative for out-of-line code).** A Debug build
   compiled with `/Gy /Ob0` (one COMDAT per function, nothing inlined) is
   linked with `/OPT:REF /VERBOSE:REF`. Every project function the linker
   discards is unreachable from the entry points; a class that is never
   constructed loses its vtable and therefore its virtual functions too.
   The product build is not touched (output in `tmproject/build/dead-code/`).
2. **Source checks** for what the linker never sees: header-only functions,
   declarations without a definition, data members never named again,
   pointers read but never assigned (always null), headers nobody includes,
   `#if 0` and commented-out code.
3. **Reachable but outside 7.48:** client handlers or senders of opcodes the
   native client does not know (`opcode-matrix.tsv`, gap B) and control IDs
   absent from every 7.48 resource (`ui-matrix.tsv`, gap X).

Limits: code reachable through a branch that never runs in 7.48 is only found
through the matrices, not by the linker. A name used only by `tests/` is
marked "uses it": removing it also removes the test. Fields of wire and
data-file structures are layout, so unused ones are counted, not proposed for
removal.

```powershell
python .agents/research/dead-code-map.py --build --tsv .agents/research/client748/inventory/dead-code.tsv --markdown DOCS/client/dead-code-map.md
```

## Findings and decisions (2026-10-03)

- **Done: unreachable code removed.** The 145 project functions the linker
  discarded and the nine translation units without a reachable function
  (`TMFlail`, `TMEffectBillBoard4`, `TMEffectGold`, `TMSkillLusterFurnish`,
  `TMSkillSnow`, `SButtonBox`, `RenderDeviceDiagnostics`, plus the `JBlur` and
  `TMVideoWnd` stubs) are gone with their declarations and registrations. The
  vendored DirectX helpers (`DXUtil`, `DirShow`, `dsutil`) stay.
- **Done: stubs removed.** The plain functions that did nothing (web-browser
  switch, demo/video/blur, `OnPacketNuke`, `OnPacketAutoKick`,
  `OnPacketRandomQuiz`, `DrawCustomFireWork`, `OnKeyDebug`, `OnKeyReverse`,
  the `EventTranslator` IME/mouse stubs, the guild-battle HP/MP setters and the
  field/entity 0x105/0x106 no-ops) were removed with their callers; behavior is
  unchanged because every one of them was empty. 0x1C5, 0x1C6 and 0x2C8 are
  native receivers the server never sends: they are now ignored, as their empty
  handlers already did. The 52 empty virtuals left are base-class defaults.
  Each change is recorded as a reviewed removal in the relocation gates.
- **Pointers never assigned** (5): `m_pJPNBag_Day2`, `m_pMoney2`,
  `m_pInvPageBtn4`, `m_pRPSGamePanel` (7.69 HUD) and
  `HudController::Object_World.inventarioGrid`. The last one is read by the
  water-scroll macro (`MacroLevel.cpp`) and fed by opcode 0x755, which the
  server never sends: the whole macro path is dead.
- **Receive handlers for opcodes nobody sends** (10): 0x1CF/0x1D0/0x301 (RMB
  cash and shop), 0x457 (tower war), 0x755 (water macro), 0x2132 (play info),
  0x5000 (EXP message panel), 0x7DB (China playtime), 0xBFF (encode) and
  0xADA (server-list extension). None is native and the server never sends
  them. Recommendation: remove them with their features unless a feature is
  wanted, in which case it becomes a coordinated extension with a server side.
  The coordinated extensions 0x105/0x106, 0x10A, 0x2D4, 0x2E4/0x2E5 and
  0x7F10/0x7F11 stay.
- **Native gap found while mapping:** native `FUN_004776c3` (field
  `FrameMove`) switches the town/zone music and sends 0x291 (ChangeCity, 16
  bytes) when the player enters another town, also updating the selection
  screen's home town. The TMProject only had this in the 7.69 branch of
  `FrameMove`, which the 7.48 runtime never ran, so the client never sent
  0x291 (the server handles it). Port it as `PARIDADE_NATIVA`.
